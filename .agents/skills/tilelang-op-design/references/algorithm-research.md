# 算法调研方法论（Phase R 执行标准）

> 本文件是 skill Phase R（算法调研）的执行标准，也是 Stage 2 维度 8 调研复核的对照基准。核心思想：**调研先于优化、优化先于实现**。对同一数学语义，算法族的选择（两遍还是单遍、materialize 还是 online、直接法还是变换域）对性能的影响通常大于后续 tiling / 流水优化；设计阶段必须先完成算法族调研（调研四问），再进入公式优化（Phase 2）与 tiling / 流水设计。简单算子允许轻量调研，但四问不可跳过。

## 1. 执行位置与调研对象

| 任务类型 | 执行位置 | 说明 |
|----------|---------|------|
| 非迁移任务 | Phase 1（输入解析与算子特征分析）之后、Phase 2 之前 | Phase 1 的算子类别与复杂度级别判定决定调研深度（§2） |
| 迁移任务 | Phase M0（源算子三问解读）之后、Phase M1（耦合性判定与 NPU 重设计）之前 | 调研结论是 M1 判定与重设计的**输入**：源算法与调研候选同台比较，重设计可直接承接调研选定的算法族（§0.6 引用 §1.6.0） |

- **调研对象：同一数学语义的算法族**——所有能算出相同结果（数学等价或容差内等价）的算法结构。输入公式 / 源算法**只是基线候选之一**，不得当作唯一算法。
- **产出**：`DESIGN.md` §1.6.0；调研结论驱动 §1.4 算法描述与 §1.6.1–§1.6.3 的分析对象（迁移任务另驱动 §0.5/§0.6 的处置）。

## 2. 调研深度分级

| 算子特征（Phase 1 / M0 判定） | 调研深度 | 要求 |
|------|------|------|
| 单步逐元素 / 纯搬运（无规约、无窗口、无矩阵） | 轻量调研 | 四问各一行结论即可，但**必须逐问回答并给依据** |
| 规约 / 统计 / 窗口 / 矩阵 / 多步 / 融合类 | 完整调研 | 候选表逐项展开：R1 候选表、R3 四口径对比表、R4 逐候选评估 |

## 3. 调研四问

### R1 有没有等价化简公式？

- **回答方式**：① 对照 §5 常见算子族参考表的命中行（必查）；② 数学恒等变形自查（代数化简、降代换、结构重排）；③ 本仓 `examples/` 与 pattern-library 同类实现所用公式；④ 本地源未覆盖时可互联网检索补充候选（webfetch，若可用；纪律见 §6 第 6 层）。
- **候选表必须含基线**（输入公式 / 源算法）；每个候选一行：公式/结构、等价性初判（数学恒等，或容差内等价 + 舍入影响方向）、收益方向（少算什么 / 少搬什么）。
- **与 §1.6.1 的分工**：R1 只做候选识别与初判；采纳项的等价论证与收益量化在 §1.6.1 完成（不重复论证）。
- **完成标准**：参考表命中行全部评估；基线之外至少覆盖了恒等变形空间；无候选时写明结构原因。

### R2 有没有在线算法？

- **定义**：单遍扫描、O(1)（或 O(tile)）中间状态的流式变体。如 online softmax（分块 running max/sum + 重缩放）、Welford 增量统计、分块归约 + 合并。
- **回答方式**：① 查 §5 参考表；② 迁移任务看 §0.4——源算法已用 online 手段是"存在在线算法"的直接证据；③ 结构判据：任何可分解为 **running 统计量**（和 / 平方和 / max / 计数）的算子，原则上存在在线变体；逐元素映射无跨元素依赖，单遍即天然在线；④ 上述仍不确定时可互联网检索该算子族的流式/online 变体（webfetch，若可用；纪律见 §6 第 6 层）。
- **收益口径**：数据扫描遍数（两遍/三遍 → 单遍）、中间缓冲（O(N) → O(tile)）、UB 驻留可行性（行/tile 能否驻留 192KB）。
- **完成标准**：结论必须是明确的「有」（候选纳入 R3/R4 对比）或「无」（写明结构原因，如"输出依赖全局 argmax 索引，无法增量更新"——注意这类断言须结构上成立）。

### R3 算法复杂度是否过高？（候选间量化对比）

- **四口径（缺一不可）**：
  1. **FLOPs**：乘加 = 2；超越函数按向量单元相对吞吐折算（折算系数标注为估算）；
  2. **访存量 Bytes**：GM 流量 = 输入读 + 输出写 + 中间 GM 往返（分母是不可消除的 I/O）；
  3. **数据扫描遍数**：同一数据的 GM 重复读取次数；
  4. **中间缓冲峰值**：决定 UB 驻留 / L1 中转 / 落 GM。
- **附加维度**：可并行度（能拆给多少核）、跨核归并代价（需要跨核同步 / 两阶段 kernel 的候选计入）。
- **基线候选必须在表中**；数字可估算，但口径必须写清（每项含什么、不含什么）。
- **完成标准**：候选 × 口径对比表齐全；选定或并列结论明确；并列（判定裕度小）→ 交 §1.6.3 布局分析 / 实验裁决模式决胜，不得纸面拍板。

### R4 算法是否硬件亲和？（逐候选评估）

- **检查清单**：
  1. **计算单元匹配**：MAC 密集段 → Cube（分形 16 对齐、L0A/L0B/L0C 路径）；逐元素 / 规约 / 超越函数 → Vector。主导计算落错单元（如大段数据串行标量累加）→ 重度失分；
  2. **片上容量**：工作集 vs UB（192KB）/ L1（512KB）/ L0C（128KB）；中间缓冲峰值超容量的候选要么分块（引入重算）要么落 GM（引入访存）；
  3. **对齐 / 整除**：尾轴 32B、分形 block ≥ 16、向量宽度整除（fp16/bf16 ×8、fp32 ×4）；
  4. **静态边界**：循环边界可否静态化（动态 shape 依赖需评估）；
  5. **流水可融合性**：多阶段可否 `T.Pipelined` 双缓冲；Cube 段与 Vector 段可否 CV 融合并行；
  6. **跨核结构**：归并是否需要 `sync_block_set/wait` 或两阶段 kernel（代价同步计入 R3）。
- **负向淘汰必须给依据**——与 SKILL.md「弃选论证证据规则」同口径：附已核对的 `docs/`、`testing/`、`examples/` 路径与限制条款，或显式标注「未文档化假设 + 估算依据」；代价类论断先查 pattern-library §1/§2 实测条目。
- **完成标准**：每个 R3 存活候选逐项检查；亲和性差异写明（它是候选排序的重要维度，不只是过滤器）。

## 4. 调研结论规范（§1.6.0 落笔要求）

1. **选定算法族 + 关键依据**（指向 R1–R4 表中的复杂度数字、亲和要点）。
2. 与基线（输入公式 / 源算法）的**结构差异**一句话。
3. **「无更优替代」结论必须写明调研范围**（查过的参考表条目 / examples / pattern-library 条目 / 结构分析结论）——禁止空白或一句"没有"。
4. **下游约束**：§1.4 算法描述、§1.6.1–§1.6.3 的分析对象 = 选定算法；迁移任务 §0.5/§0.6 的处置与之一致（调研选 A、§0.6/§6 设计 B → 不一致，Stage 2 判 fail）。
5. **迁移任务**：源算法已识别的优化手段（§0.4）在调研后**不得静默丢弃**——源算法被替换时，逐项说明其优化意图由选定算法的什么结构承接（或为何不再需要）。

## 5. 常见算子族替代算法参考表

> 命中行是 R1/R2 的**必查清单**（下界不是上界）：命中行的候选必须评估，但调研不得止步于参考表——结构判据（§3 R2）与外部已知算法仍须过一遍。表内条目涉及 API 时仍须本地佐证（`examples/` / `docs/`）——**算法思路与 API 存在性是两回事**。

| 算子族 | R1 等价化简候选 | R2 在线变体 | R3 复杂度要点 | R4 亲和要点 |
|--------|----------------|------------|--------------|------------|
| softmax / log-softmax / logsumexp | 减 max 稳定化（必选）；log-softmax 直接由 logsumexp 表示；exp → exp2·log2e 缩放 | online softmax（分块 running max/sum + 重缩放） | 三遍（max/sum/normalize）vs 两遍 vs 单遍 online；行缓冲 O(row) vs O(tile) | 行内水平归约 vs 垂直扫描（与 §1.6.3 交互）；整行 UB 驻留；attention 场景 MixCV 融合 |
| layer_norm / batch_norm | `x/sqrt(var+ε)` → `x·rsqrt(...)`；单遍式 `var = E[x²]−(E[x])²`（须评估 fp32 累加与 catastrophic cancellation） | Welford 增量 mean/var；分块 running 统计 | 两遍扫描 vs 单遍；统计量缓冲 | 规约轴 lane 映射（见 §1.6.3）；fp32 累加路径 |
| rmsnorm | 无 mean 减法（相对 layer_norm 少一遍扫描）；rsqrt | 平方和单遍天然在线 | 平方和单遍；无均值遍 | 同上 |
| attention | scale 融入 Q/K；softmax 分母倒数乘法化 | flash 结构：online softmax + 分块 KV，O(N²) 中间矩阵 → O(N) | materialize O(N²) 访存/缓冲 vs flash O(N) 缓冲（FLOPs 同阶） | Cube GEMM 分块 + Vector online softmax 流水（MixCV）；L0C/UB 容量定 tile |
| 卷积 | im2col + GEMM；implicit GEMM；Winograd（小核乘法次数↓加法次数↑，须按单元吞吐比评估） | 滑窗天然流式 | direct vs im2col：FLOPs 同阶、访存与单元利用率不同；Winograd 乘法按窗口比例下降 | Cube 路径分形对齐；Vector 直接窗口的 C 轴整除性；im2col 展开缓冲 |
| 池化 | avg pool = 常数权重卷积；sum pool × 常数 = avg pool | 滑窗天然流式 | 窗口重叠数据的重复读 | C 轴向量轴；跨步系数（见 §1.6.3） |
| 规约 / 统计（sum/max/mean/var/norm/argmax） | max + sum 合并扫描；和与平方和一次扫描 | 分块归约 + 合并（两阶段 / 树形）；Welford | 扫描遍数；跨核归并代价 | 水平 vs 垂直 lane 映射；跨核 sync 代价 |
| top-k / 排序 | 部分选择 vs 全排序；分块 top-k + 归并 | 分块 + 归并 | O(N·k) vs O(N log N) | 归并链的核内结构与缓冲 |
| gemv / 矩阵-向量 | GEMM 分形路径（Cube，load_nd2nz）vs Vector 规约累加 | split-K 分块累加 | Cube 利用率 vs 归约代价 | K 维分块与 L0 容量 |
| 三角求解 / 求逆 | 只需解不需逆时：直接求解替代显式求逆（同阶但常数更小、数值更稳）；对角/三角特例降阶 | — | 求逆 + 乘法 vs 单次求解；特例 O(n²)/O(n) | Cube 三角 GEMM 支持 |
| elementwise 链 / 激活 | 公共子表达式消除；除法乘倒数；cast 链合并 | 逐元素映射天然单遍 | 融合消除中间 GM 往返（访存收益主导） | 单遍 Vector 流；dtype 路径 |
| 转置 / 重排 | 核内融合转置链（UB 级，实测 ~µs 级）vs host permute（~百 µs 级） | 分块转置 | GM 流量不变，代价在向量管线开销 | T.transpose dtype 矩阵（fp16/fp32 ✓，bf16/整型 ×）；UB 容量 |

## 6. 调研信息源（优先级沿用 [info-sources.md](info-sources.md)）

1. 本参考表 §5（命中行必查）；
2. pattern-library.md §4 案例索引（同类算子正/反例）+ §1 实测模式与代价；
3. 本仓 `examples/` 同类实现所用算法；
4. 源算子及其依赖库（迁移任务：§0.3/§0.4 的算法与优化手段是"该算子族存在什么算法"的直接证据）；
5. 外部已知算法（模型知识：PyTorch / CUDA 生态公开算法）：**只取算法思路**；涉及本项目 API 存在性必须本地佐证；涉及性能代价必须实测或标注「未文档化假设 + 估算依据」；
6. **互联网检索（webfetch，若环境可用；可选补充层）**：查论文（arXiv 等）、开源实现（PyTorch / CUTLASS / flash-attention 等仓库）、厂商文档（NVIDIA / 昇腾官方）、技术博客——用于补足模型知识与参考表未覆盖的候选（新算子、罕见算子族、最新算法进展）。**使用纪律**：
   - **只取算法思路**（算法结构 / 公式 / 复杂度结论），外部 API 不可直接采用——本项目 API 存在性必须本地佐证（`examples/` / `docs/Tilelang.language/`）；
   - **外部性能数字只可作候选排序参考**（GPU 上的加速比 ≠ NPU 上的判定依据）——涉及本项目的性能代价必须实测或标注「未文档化假设 + 估算依据」；
   - **来源可溯**：§1.6.0 引用互联网来源的候选须记录来源（URL / 论文标题+作者年份 / 仓库路径）与访问日期；检索不到时如实记录「已检索未命中」（含检索关键词），不得编造来源或结论；
   - **优先级最低**：与本地信息源（参考表 / pattern-library / examples / 源码）矛盾时以本地为准；
   - **降级处理**：网络不可用 / 工具缺失 / 超时 → 按第 5 层模型知识 + 本地源继续调研并在 §1.6.0 如实记录，不阻塞设计流程；
   - **适用时机**：参考表未命中 / R2 结构判据不确定 / R1 候选空间存疑 / 用户指定了新论文或新算法时；简单算子轻量调研通常无需联网。

## 7. 反模式（禁止行为）

- ❌ 跳过调研，把输入公式 / 源算法当作唯一算法直接进入公式优化 / tiling 设计。
- ❌ 四问只答了化简公式一问（漏在线算法 / 复杂度 / 硬件亲和）。
- ❌ 复杂度只比 FLOPs，不比访存 / 遍数 / 中间缓冲（带宽受限算子上访存才是主导项）。
- ❌ "无在线变体 / 无化简公式 / 无更低复杂度算法"负向断言无结构依据，或与参考表、源码证据（源算法已用 online 手段）矛盾。
- ❌ 调研选定算法与 §1.4 / §1.6.1–§1.6.3 / §6 分析对象脱节（调研选 A、设计做 B）。
- ❌ 迁移任务中源算法的优化手段被调研替换后静默丢弃（优化意图无承接说明）。
- ❌ 调研候选的采纳跳过等价性论证（采纳项必须进 §1.6.1 完成四要素论证）。
- ❌ 互联网检索结果不记来源（URL/论文/仓库 + 访问日期），或把外部 API、GPU 平台性能数字直接当作本项目的 API 存在性与性能判定依据。
